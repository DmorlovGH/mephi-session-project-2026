# Сессионный проект по безопасности операционных систем

**Образовательная программа:** магистратура НИЯУ МИФИ  
**Дисциплина:** Безопасность операционных систем  
**Операционная система:** РЕД ОС 8.0.3 Standard Server Minimal  
**Номер студента:** 375445

## 1. Установка операционной системы и настройка сети

Установлена РЕД ОС 8.0.3 Standard Server Minimal в виртуальную машину VMware Workstation.

Настроены:
- Имя узла: `mephi-2026.domain.local`.
- Сетевой интерфейс: `ens160`.
- Получение сетевых параметров по DHCP.
- Сетевое подключение через VMware NAT.

Проверена доступность адреса `8.8.8.8` командой `ping -c 4 8.8.8.8`.

**Подтверждение:** [ping.out](ping.out).

## 2. Управление программным обеспечением

Выполнено обновление операционной системы через `dnf upgrade`.

Установлены пакеты:
- `nginx`;
- `libcap-ng-utils`;
- `tcpdump`.

RPM-пакет `tcpdump` предварительно загружен в `/tmp` с помощью `dnf download`, затем установлен командой `rpm`.

Дополнительно установлены утилиты, необходимые для настройки SELinux, проверки PAM и работы с Git.

**Подтверждение:** [dnf.out](dnf.out).

## 3. Работа с файловой системой

Подключён дополнительный виртуальный диск `/dev/sdb`.

На диске создан раздел `/dev/sdb1` с файловой системой ext4 и меткой `MEPHI_WEB`.

Раздел смонтирован в `/mephi-web`.

В `/etc/fstab` настроено постоянное монтирование по метке:

```text
LABEL=MEPHI_WEB /mephi-web ext4 defaults 0 2
```

Корректность автоматического монтирования подтверждена после перезагрузки ОС.

**Подтверждения:** [fstab](fstab), [stat.out](stat.out).

## 4. Управление службами

Установлен и настроен веб-сервер nginx.

Служба nginx запущена и включена в автозагрузку с помощью systemctl.

После перезагрузки РЕД ОС подтверждены:
- состояние службы: active (running);
- автоматический запуск nginx;
- доступность веб-сервера по HTTP.

**Подтверждение:** [journalctl.out](journalctl.out).


## 5. Управление доступом: DAC, Linux capabilities и SELinux

### 5.1. Дискреционное управление доступом (DAC)

Создан каталог /data/mephi-2026.

Настроены пользователи и группы:
- user1 — UID 5501, группа developers;
- user2 — UID 5502, группа developers;
- user3 — UID 5503, группа developers;
- curator1 — UID 5504, группа curators;
- curator2 — UID 5505, группа curators;
- группа curators — GID 4444.

Для каталога настроены права доступа и ACL:
- пользователи группы developers могут читать и изменять файлы;
- пользователи группы curators могут читать файлы, но не изменять их;
- остальные пользователи не имеют доступа.

На каталоге установлен бит SGID, обеспечивающий наследование группы developers новыми файлами и подкаталогами.

Настроены ACL по умолчанию: разработчики получают права чтения и записи, кураторы — только чтения, остальные пользователи не получают доступа. Для каталогов дополнительно предусмотрены права, необходимые для перехода внутрь них. Наследование проверено на новых файлах и вложенных каталогах.

Проведены функциональные проверки:
- user1, user2 и user3 создавали, читали и изменяли файлы;
- curator1 успешно прочитал файл;
- curator1 и curator2 не смогли записать данные;
- постороннему пользователю доступ был запрещён;
- наследование прав проверено во вложенном каталоге.

### 5.2. Linux capabilities

Для программы /usr/sbin/tcpdump назначены следующие capabilities:

- cap_net_admin;
- cap_net_raw.

Режим назначения: eip (effective, inheritable, permitted).

Это позволяет запускать tcpdump для захвата сетевых пакетов без использования SUID и без запуска программы от имени root.

Функциональная проверка выполнена от имени user1:
- tcpdump запущен на интерфейсе ens160;
- успешно захвачен один сетевой пакет;
- SUID-бит на исполняемом файле отсутствует.

**Подтверждение:** [getcap.out](getcap.out).

### 5.3. Мандатное управление доступом (SELinux)

SELinux работает в режиме Enforcing.

Для каталога /mephi-web и его содержимого настроен постоянный контекст безопасности httpd_sys_content_t.

Для настройки использованы:
- semanage fcontext — регистрация постоянного правила маркировки;
- restorecon — применение контекста к каталогу и файлам.

В конфигурации nginx корневой каталог веб-сервера изменён на /mephi-web.

Проверено:
- каталог /mephi-web имеет контекст httpd_sys_content_t;
- файл index.html имеет контекст httpd_sys_content_t;
- nginx успешно обслуживает страницу при SELinux Enforcing;
- после перезагрузки настройки сохраняются.

**Подтверждения:** [getenforce.out](getenforce.out), [curl.out](curl.out).

## 6. Аутентификация и парольная политика

Для локальной консоли РЕД ОС настроено ограничение входа пользователей curator1 и curator2.

Ограничение реализовано с помощью PAM:
- в /etc/pam.d/login подключён модуль pam_access.so;
- правила доступа размещены в /etc/security/mephi-console-access.conf;
- правило подключено к PAM-конфигурации локального консольного входа (`/etc/pam.d/login`); конфигурация PAM для SSH (`sshd`) не изменялась.

Проведены функциональные проверки непосредственно в консоли VMware:
- user1 — успешный вход, команда whoami вернула user1;
- curator1 — вход отклонён, Permission denied;
- curator2 — вход отклонён, Permission denied.

Дополнительно проверены правила PAM с помощью pamtester.

Настроена парольная политика:
- минимальная длина пароля — 12 символов (minlen = 12);
- максимальный срок действия пароля — 90 дней (PASS_MAX_DAYS 90).

Для созданных пользовательских учётных записей максимальный срок действия пароля установлен с помощью chage.

**Подтверждения:** [pwquality.conf](pwquality.conf), [passwd](passwd), [shadow](shadow), [group](group).

**Примечание по безопасности:** публикуемый файл shadow является обезличенной копией /etc/shadow. Во всех строках поле хеша пароля заменено на [REDACTED]. Оригинальные хеши паролей не публикуются.
